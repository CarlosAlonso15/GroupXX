Análisis del Dataset y Estrategia de Nombrado de Recursos

Documento de análisis técnico correspondiente a la segunda práctica (Hands-on Assignment 2) del proceso de generación de Datos Enlazados (Linked Data).

1. Análisis del Dataset (Analyse Data Set)

El dataset analizado corresponde al inventario público de puntos de recarga de vehículos eléctricos en la ciudad de Madrid, ubicado en el repositorio del grupo bajo la ruta csv/vehiculos_electricos.csv.

1.1. Análisis Cuantitativo y Estructural

  • Volumen de datos: El fichero contiene un total de 122 registros (estaciones de recarga) distribuidos en la vía pública y aparcamientos municipales.
  • Estructura de columnas (Esquema): El dataset consta de 12 atributos descriptivos:
    • COD_DIS / DISTRITO: Código numérico y nombre del distrito administrativo de Madrid.
    • COD_BAR / BARRIO: Código numérico y nombre del barrio correspondiente.
    • UBICACIÓN / EMPLAZAMIE: Dirección postal descriptiva del punto y tipo de emplazamiento (vía pública, etc.).
    • INFO_ADICI: Información adicional de interés sobre la localización o acceso.
    • Nº_EQUIPO: Identificador numérico del equipo de recarga.
    • CARACTERÍ: Especificaciones técnicas de potencia y tipos de conectores (ej. 50 kW 2 conectores CC y 1 conector AC).
    • OPERADOR: Empresa o entidad gestora del punto de recarga (ej. IBERDROLA, WENEA, etc.).
    • POINT_X / POINT_Y: Coordenadas espaciales proyectadas (sistema métrico UTM / EPSG:25830).

1.2. Rangos de Valores y Tipos

Los datos presentan una alta consistencia, con variables de texto para denominaciones administrativas, cadenas normalizadas para operadores y valores numéricos proyectados en coordenadas espaciales que permiten su conversión directa a coordenadas geográficas estandarizadas (WGS84).

3. Estrategia de Nombrado de Recursos (Resource Naming Strategy)

Para asegurar la persistencia, limpieza y cumplimiento de las recomendaciones del W3C en la Web Semántica, se ha diseñado la siguiente política de URIs:

3.1. Dominio Base

Se establece un dominio base orientado al proyecto de Smart City del grupo:

http://smartcity.example.org/group01/

3.2. Patrones de URIs

  • Ontología (Esquema, Clases y Propiedades):
    http://smartcity.example.org/group01/ontology#
    Ejemplo de clase: http://smartcity.example.org/group01/ontology#ChargingStation
  • Instancias (Recursos de datos individuales extraídos del CSV):
    http://smartcity.example.org/group01/resource/{tipo}/{id}
    Ejemplo de instancia: http://smartcity.example.org/group01/resource/ChargingStation/EV-001

3.3. Negociación de Contenido (Content Negotiation)

El servidor web implementará mecanismos de negociación de contenido HTTP mediante las cabeceras Accept, permitiendo que los usuarios humanos obtiendan una representación visual en formato HTML y los agentes software o aplicaciones semánticas reciban los datos estructurados en formatos RDF como Turtle o RDF/XML.

Nota de implementación: Este esquema sienta las bases para la posterior conversión de los 122 registros del CSV en triples RDF utilizando la ontología ligera desarrollada en el entregable ontology/vehiculos-electricos.ttl.
